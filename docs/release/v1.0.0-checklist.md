# v1.0.0 release checklist

The first release is created only after the documentation PR is merged and the repository owner explicitly approves the tag. The tag is not created from a feature branch.

## Automated gates

- [x] `main` is protected and accepts changes through pull requests.
- [x] Backend and Frontend checks are required.
- [x] Locked NuGet restore and npm clean install are enforced.
- [x] NuGet, npm, and dependency-review vulnerability gates are enabled.
- [x] Domain, application, integration, frontend, and AI evaluation tests are required.
- [x] GitHub Actions and local container images are pinned to reviewed commits/digests.
- [x] Dependabot, secret scanning, push protection, and private vulnerability reporting are enabled.

## Product and documentation gates

- [x] The deterministic cancellation flow is implemented for penalty, no-penalty, cancelled, and expired contracts.
- [x] Local hybrid retrieval, citations, grounded bilingual answers, and insufficient-evidence refusal are implemented.
- [x] Safe tool preparation and explicit confirmed writes use the same deterministic command path.
- [x] The React workspace supports English and Brazilian Portuguese.
- [x] Local OpenTelemetry, privacy filtering, and the optional Aspire Dashboard are documented.
- [x] The v1 security boundary and residual risks are documented.
- [ ] The interview-ready README, screenshots, bilingual demo script, and cost guide are merged to `main`.
- [ ] All README and documentation links are checked from the merged commit.
- [ ] A final clean-clone smoke test is completed using only documented prerequisites and commands.

## Human approval gates

- [ ] Review screenshots and public-facing wording for portfolio use.
- [ ] Confirm that no real customer data, personal data, API key, access token, populated `.env`, or local evaluation output is included.
- [ ] Approve the release notes in [v1.0.0 release notes](v1.0.0-notes.md).
- [ ] Approve creation of the immutable `v1.0.0` tag and GitHub release.

## Final validation commands

Run from a clean checkout of `main`:

```powershell
dotnet restore ContractIQ.slnx --locked-mode `
  -p:NuGetAudit=true `
  -p:NuGetAuditMode=all `
  -p:NuGetAuditLevel=moderate `
  -p:TreatWarningsAsErrors=true
dotnet list ContractIQ.slnx package --vulnerable --include-transitive --no-restore
dotnet format ContractIQ.slnx --verify-no-changes --no-restore
dotnet build ContractIQ.slnx --configuration Release --no-restore
dotnet test ContractIQ.slnx --configuration Release --no-build
dotnet tools/ContractIQ.AiEvaluator/bin/Release/net10.0/ContractIQ.AiEvaluator.dll --mode offline
```

```powershell
Set-Location src/ContractIQ.Web
npm ci
npm audit --audit-level=high
npm run lint
npm run test
npm run build
```

Required GitHub Actions are the authoritative release gate if the local .NET SDK exhibits the known Windows worker-process issue.

## Release procedure after approval

1. Confirm the documentation PR is merged and `main` is clean.
2. Confirm required checks passed on the merge commit.
3. Create an annotated `v1.0.0` tag on that exact commit.
4. Push the tag.
5. Create a GitHub release using [the prepared release notes](v1.0.0-notes.md).
6. Confirm the release page links to the immutable tag and source archives.
7. Close issue #14 only after the public release is visible.

The release operation is deliberately separate from this documentation change so the owner can review the public presentation before creating an immutable version marker.
