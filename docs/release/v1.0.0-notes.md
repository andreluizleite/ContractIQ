# ContractIQ v1.0.0

ContractIQ v1.0.0 is the first interview-ready release of the local contract intelligence portfolio application.

## Highlights

- bilingual React contract workspace for English and Brazilian Portuguese;
- deterministic cancellation eligibility, notice dates, chargeable periods, and penalties owned by the .NET domain model;
- PostgreSQL persistence, idempotent commands, transaction boundaries, and fictional seed scenarios;
- local hybrid retrieval across versioned contracts and policies using PostgreSQL full-text search, pgvector, and Reciprocal Rank Fusion;
- grounded answers with application-owned citations and insufficient-evidence refusal;
- provider-neutral `Microsoft.Extensions.AI` integration with local Ollama or optional hosted Kimi;
- safe assistant tool calling that can prepare but cannot automatically execute a cancellation write;
- explicit user confirmation and deterministic CQRS revalidation before persistence;
- OpenTelemetry traces, metrics, logs, and an optional local Aspire Dashboard;
- automated domain, application, integration, frontend, security, and deterministic AI evaluation gates;
- protected GitHub workflow with dependency locks, vulnerability audits, Dependabot, and secret-scanning push protection.

## Run the release

The default structured demonstration requires .NET 10, Node.js 24 LTS, Docker Desktop, and Git. It creates no Azure resource and needs no hosted-model key.

See the repository [README](../../README.md) for quick start and the [bilingual interview guide](../demo/interview-guide.md) for the complete demonstration.

## Scope and safety

This version is a local portfolio demonstration with fictional data. Anonymous API access is allowed only in the ASP.NET Core `Development` environment, and the API refuses to start in `Staging` or `Production` until an authenticated deployment profile is implemented.

ContractIQ does not provide legal advice. Microsoft Entra ID, Microsoft Foundry, Azure AI Search, hosted deployment, and tenant isolation remain optional post-MVP roadmap work.

## Known boundaries

- in-process rate limits are not distributed abuse protection;
- local PostgreSQL retrieval is not Azure AI Search BM25 or semantic ranker;
- Ollama performance depends on local CPU, RAM, and model selection;
- Kimi usage is opt-in, consumes provider credits, and should use only fictional data;
- production authentication, authorization, networking, backups, secrets, and cloud cost governance are not part of this local release.
